# 사례대장 이식용 패키지 (Stage 1) — 스키마·규칙

> 생성 2026-08-17. 원본 = `학습노트/90_사례대장.md` (부칙 P 기반 사례 대장).
> 목적 = 금융공자 가이드북 정독으로 축적한 **매매 기법 검증 사례 333건**을, 어떤 LLM·도구에서도 바로 읽고 분석·검색할 수 있는 정형 데이터로 제공한다.
> 본 패키지는 **단권화 패키지의 「사례 축」**이다. 개념층(기법·원칙 통합)과 개념↔사례 크로스링크는 Stage 2에서 추가된다.

| 파일 | 내용 |
|---|---|
| `cases.csv` | 333건 사례 (UTF-8 BOM, Excel 한글 정상). 표 분석·필터용 |

---

## 2. 이 데이터가 무엇인가

한국 주식 트레이딩 가이드북(금융공자 가이드북 시리즈: 단타·스윙·재료매매 트랙)을 페이지 단위로 정독하며, 저자가 제시한 **기법의 실제 종목 사례**를 하나씩 뽑아, **KRX(한국거래소) Open API 실측**으로 발생일·시가/고가/저가/종가·거래대금·등락률을 검증해 축적한 것이다.

- 목적은 저자의 **정성적(定性的) 기법 서술을 정량 검증 가능하게** 만드는 것. 그래서 각 사례에 **라벨(성공/실패)** 과 **시점(발생일)** 을 붙였다.
- **실패·매매불가 사례도 반드시 포함**한다(생존 편향 방지). 현재 성공 271 / 실패 62.

---

## 3. 스키마 (필드 정의)

| 필드 | 타입 | 설명 |
|---|---|---|
| `case_id` | string | `CASE-####` 고유 ID (0001~0333, 연속·무결) |
| `seq` | int | 일련번호 정수 (정렬용) |
| `label` | enum | **`성공` / `실패` / `판정보류`** — ★저자가 그 사례를 **제시한 목적**(성공 예시인가 실패 경고인가)이지, 실제 손익이 아님 |
| `date` | date(YYYY-MM-DD) | **발생일** = 매매 관측일 = 차트상 기준봉(장대양봉·상한가)일. 분봉 최고가 = KRX 일봉 고가로 대조 |
| `name` | string | 종목명 (발생일 당시 사명 기준. 사명변경은 `evidence`에 병기) |
| `code` | string | 종목코드 6자리 (KRX 실측 확정) |
| `tag_main` | string | 기법 대분류 (원문 태그의 앞부분) |
| `tag_sub` | string | 기법 소분류 (원문 태그의 `/` 뒷부분) |
| `tag_full` | string | 원문 태그 전체 |
| `g_ref` | string | 정독 노트 앵커 G번호(들), `;` 구분. 원문 근거로 역추적하는 키 |
| `source` | string | 출처 (권·자료집·G번호 + 검증 방법) |
| `evidence` | string | 근거 수치·맥락(자연어): 재료, OHLC, 거래대금, dedup·별건·사명변경 주석 |

### 라벨 해석 주의 (중요)
`label`은 **저자의 제시 의도**다. 예: "재료 소멸 후 급락" 사례는 저자가 *매도 타이밍을 가르치려고* 든 것이라 `실패`로 태깅되지만, "그 시점에 팔았다면 성공"이라는 교훈이다. 손익 백테스트 라벨이 아니다.

### 발생일 정의
`date`는 **기준봉일(급등 관측일)**. 범위형 재료(정치 테마 등)는 국면 내 상한가·최대 장대양봉일을 KRX로 특정했다. 재료 뉴스일과 기준봉일이 다르면 **차트 기준봉(캔들) 실제일**을 우선한다.

## 4. 태그 체계

`tag_main`은 정독 진행 순서대로 배치별 명명이라 **입도(粒度)가 균일하지 않다**(정규화는 Stage 2 과제). 분석 시 아래 **상위 계열로 묶어** 쓰면 좋다.

| 상위 계열 | 포함 tag_main(예) | 대략 건수 |
|---|---|---|
| 상한가 따라잡기 | `상따`, `상따(상한가)` | ~66 |
| 갭하락·낙폭과대 단타 | `갭하락 단타`, `낙폭과대(데이트레이딩)`, `낙폭과대(낙주)` | ~58 |
| 적정거래대금·기준봉·데이트레이딩 | `적정거래대금…`, `기준봉 패턴`, `기준봉 매매`, `데이트레이딩 매매(5-3권…)`, `종가관리…`, `수급유입…` | ~135 |
| 짝짓기(테마 동반) | `짝짓기` | ~17 |
| 재료매매 | `재료매매` (매각·경영권·정치테마·정책·신선재료 등) | 49 |
| 기타 | `돌파 매매 흐름⑤`, `볼린저밴드 눌림목`, `차트 방향 전환` 등 | 소수 |

`tag_sub`에 세부 유형(예: `상한가풀림`, `하한가 반등`, `10 예시집`, `정치 재판(재료 소멸)`)이 들어 있다.

---

## 5. G-spine (정독 노트 앵커)

`g_ref`의 `G####`는 정독 노트(`학습노트/08~13_*_정독.md`, `02x_재료매매`)의 문단 번호다. G번호는 **트랙 전체를 관통하는 단일 연속 축**이라, 이 값으로 사례 → 원문 서술을 정확히 역추적할 수 있다. Stage 2에서 개념 색인(`91_개념인덱스`)과 이 G번호로 크로스링크한다.

---

## 6. 부칙 P 등록 규칙 (요약)

이 대장의 등록 규약. 데이터 해석·확장 시 동일 규칙을 따른다.

1. **필수 필드**: 기법 태그 / 종목명·코드 / **발생일** / 라벨 / 출처. 하나라도 없으면 등록 금지.
2. **발생일 필수** — 기간 분할 안정성 검증의 기준축.
3. **라벨 = 저자 제시 목적** (성공/실패/판정보류). 실패·매매불가도 반드시 등록.
4. **검증** = KRX Open API 실측(거래대금·OHLC). pykrx 미사용, KRX Open API만.
5. **동일 종목이라도 발생일이 다르면 별건**(다른 재료·국면). `evidence`에 별건/ dedup 주석.
6. **무결성**: `case_id` 연속(현재 1~333), 중복·gap 0.

## 8. 활용 예시

**LLM에 그대로 투입** — cases.json을 컨텍스트로 넣고:
- "라벨이 실패인 상따 사례만 골라 공통점을 요약해줘"
- "2022년 재료매매/정치테마 사례의 발생일·등락률을 표로"
- "기준봉 패턴(tag_main) 성공 사례의 거래대금 분포를 설명해줘"

**표 도구(Excel/pandas)** — cases.csv 열어 `label`·`tag_main`·`date` 필터/피벗.

**원문 역추적** — 관심 사례의 `g_ref`(예: `G6123`)로 정독 노트에서 저자 원 서술을 확인.

## 9. 한계·주의

- `tag_main` 입도 불균일 (정규화 = Stage 2). 분석 시 §4 상위 계열로 묶을 것.
- `evidence`는 자연어 필드라 수치 파싱은 후처리 필요(거래대금·고가 등이 문장 안에 있음).
- 본 패키지는 **금융공자 트랙만** 포함. **와디즈 미라클은 미포함**(사례 소급 미착수).
- 라벨은 저자 제시 의도이지 백테스트 손익이 아님(§3 참조).

---

## 10. 다음 단계 (Stage 2 — 본격 단권화)

여기에 **개념층**을 얹으면 단권화 패키지가 완성된다:
1. 개념 단권 문서 (`91_개념인덱스`·`92_트랙간_충돌`·`93_오답지점` + 각 트랙 기법 요약 통합)
2. **개념 ↔ CASE ↔ G번호 크로스링크** (이 데이터의 `g_ref`가 연결 키)
3. 금융공자 ↔ 와디즈 **용어 대조표**(예: 기준봉·매집 ↔ 주포·개미털기·ABCD)

그러면 "개념 → 실증 사례 → 원문"이 한 패키지에서 순환한다.
