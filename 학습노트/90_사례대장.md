## 등록 규칙 (부칙 P 요약)

**필수 필드 — 하나라도 비면 등록 금지, 사용자에게 질문할 것**

| 필드 | 내용 |
|---|---|
| `CASE-####` | 일련번호 (0001부터) |
| 기법 태그 | 기준봉 / 낙폭과대 / 적정거래대금 / 쩜하한 / 음봉시가돌파 / 종가관리 … |
| 종목명·코드 | |
| **발생일** | **필수** (기간 분할 안정성 검증의 기준) / 분봉이면 관측 시각까지 |
| 라벨 | `성공` / `실패` / `판정보류` — ★**실패·매매불가도 반드시 등록** |
| 출처 | 책 = 권·페이지·G번호 / 실전 = "사용자 관찰" + 날짜 |
| 근거 수치 | 거래대금·등락률 등 검증용 원시값 (KRX 교차 확인값 우선) |

★**라벨 정의 (2026-08-03 확정) = 「저자가 그 사례를 제시한 목적」 기준**
- `성공` : 저자가 기법이 통한 사례로 제시 / `실패` : 저자가 손실·리스크 사례로 제시 / `판정보류` : 저자의 제시 목적이 불분명한 경우에 한함
- ★라벨은 '매매 손익'이 아니라 '저자의 제시 목적'을 기록한다. 실제 종가·등락률 등 실측 결과는 「근거 수치」에 별도 기록하며, 라벨과 반대 방향이어도 라벨을 바꾸지 않는다(예: 저자가 리스크 사례로 든 종목이 상한가 마감이어도 라벨 = `실패`). 매매 손익 기준 판정은 부칙 P-2 패턴 검증에서 별도 산출.
- [이유] 동일 사례가 기준에 따라 성공/실패 양쪽으로 읽히는 문제가 CASE-0006·0007에서 발생 → 준거를 저자 의도로 고정하여 등록자 판단 개입 차단.

**작성 원칙**
- G-노트 작성과 동시에 등록하고, G-노트에 `→ CASE-####` 역참조를 남긴다.
- ⚠️CASE 번호는 `_check_grefs.py` 검사 대상이 **아니다** → 오기 자체 검출 불가, 기재 시 주의.
- 저자의 세력 서사 등 **관측 불가 해석은 근거 수치로 쓰지 않는다**(STEP 4.7 "추론≠관측").
- 정량 규칙이 없는 서술은 "수동 판단 영역"으로 명시 구분(근사 지표로 대체 금지).
- 패턴 검증 파이프라인(부칙 P-2)은 **사용자 지시 시에만** 실행. 판정 기준은 **검증 실행 전** 합의·기록(P-3), 소급 수정 금지.
